# المرحلة 05 — لوحات المالك والمدرّس وإدارة الفريق والكورسات

## المسارات التي أُنشئت

### المالك (`super_admin`)
- `/admin` — نظرة عامة وإحصاءات آمنة (بدون أرقام مختلقة)
- `/admin/teachers` — قائمة المدرّسين مع بحث وتصفية
- `/admin/teachers/new` — واجهة إضافة/دعوة مدرّس
- `/admin/teachers/[id]` — تفاصيل، صلاحيات، تعيينات، تأكيدات حساسة
- `/admin/courses` — قائمة الكورسات مع بحث وحالات
- `/admin/courses/new` — واجهة مسودة كورس
- `/admin/courses/[id]` — تفاصيل، نشر/أرشفة (واجهة فقط)، المدرّسون المعيّنون

### المدرّس
- `/teacher` — نظرة عامة على الكورسات المعيّنة فقط
- `/teacher/courses` — قائمة التعيينات
- `/teacher/courses/[id]` — واجهة واعية بالصلاحيات (دروس/امتحانات/تقدّم)

## المكوّنات المشتركة
- `DashboardLayout` / `DashboardSidebar` / `DashboardTopbar`
- `StatCard` / `StatusBadge` / `EmptyState` / `LoadingState`
- `ConfirmationDialog` / `PermissionSwitch` / `DataTable`
- `SetupRequiredPanel` / `DisabledMutationForm` / `PageHeader`

## حدود الأدوار
- المالك فقط يصل إلى `/admin/*` عبر `requireAdmin`.
- المدرّس فقط يصل إلى `/teacher/*` عبر `requireTeacher`.
- صلاحيات المدرّس تُقرأ من `course_staff_assignments` وليس من `created_by`.
- لا تُمنح أدوار من الواجهة أو من `user_metadata`.

## سير عمل إدارة المدرّسين (مستهدف)
1. المالك يفتح إضافة مدرّس.
2. يضبط `can_create_course_drafts` عند الحاجة.
3. يعيّن كورسات مع `can_edit_content` / `can_manage_exams` / `can_view_student_progress`.
4. يمكنه إزالة التعيين أو تعطيل المدرّس بعد التأكيد.

**الوضع الحالي:** الواجهات ورسائل التأكيد موجودة، والتنفيذ الفعلي معطّل بأمان.

## سير عمل إدارة الكورسات (مستهدف)
1. إنشاء مسودة.
2. تعيين مدرّسين.
3. مراجعة ثم نشر بواسطة المالك فقط.
4. أرشفة عند الحاجة.

**الوضع الحالي:** القراءة الآمنة مهيأة عند جاهزية المخطط؛ الكتابة معطّلة.

## ما يعمل الآن
- هيكل لوحات احترافي RTL داكن بنفس الهوية البصرية.
- حراسة المسارات كما هي (fail closed).
- طبقة بيانات خادم تفشل مغلقًا إذا `NEXT_PUBLIC_DB_SCHEMA_READY` غير مفعّل.
- عدم اختلاق إحصاءات أو طلاب أو مدفوعات وهمية.

## ما هو معطّل عمدًا
- دعوة المدرّسين وتعيينهم وكتابات الكورسات والنشر.
- أي mutation حقيقية على Supabase.
- تطبيق الهجرات عن بُعد.

## الخطوات الآمنة لاحقًا
1. تشغيل اختبارات أمان SQL على قاعدة disposable.
2. تطبيق الهجرات على staging.
3. ضبط `NEXT_PUBLIC_DB_SCHEMA_READY=true` بعد التحقق.
4. ربط Server Actions بالدوال الآمنة (`admin_set_user_role`, `upsert_course_staff_assignment`, `publish_course`, …).
5. ثم فقط تفعيل الكتابة تدريجيًا مع تدقيق.

## قرارات معلّقة
- مصدر دعوة المدرّس النهائي (رابط دعوة / إنشاء حساب إداري / OTP).
- هل تُدار الترمات/الدروس داخل نفس المرحلة أم مرحلة مستقلة للمحتوى.
- شكل سجل النشاط المعتمد على `audit_logs` في الواجهة.
