# خطة أمان تخزين إيصالات الدفع (خاص)

> **لم يُنشأ أي Storage bucket في هذه المرحلة** — تخطيط فقط.

## الهدف

تخزين صور/ملفات إيصالات Instapay وVodafone Cash بشكل خاص، مع حفظ `receipt_path` فقط في `payment_requests`.

## التصميم المقترح

| العنصر | القرار |
|---|---|
| اسم الـ bucket | `payment-receipts` (private) |
| الوصول العام | ممنوع تمامًا |
| مسار الملف | `student_id/payment_request_id/uuid.ext` |
| القراءة | روابط موقّعة قصيرة العمر عبر الخادم لـ `super_admin` فقط |
| الكتابة | عبر الخادم بعد التحقق من هوية الطالب وحجم/نوع الملف |
| الأنواع المسموحة | `image/jpeg`, `image/png`, `application/pdf` |
| الحجم الأقصى | يُحدد لاحقًا (مقترح ابتدائي 5MB) |
| الحذف | لا يحذف الطالب الإيصال بعد الإرسال؛ الأرشفة قرار إداري |

## سياسات Storage المقترحة لاحقًا

- `INSERT`: الطالب فقط تحت بادئة `auth.uid()` عبر مسار خادم موثوق أو policy ضيقة.
- `SELECT`: لا مباشرة للطلاب بعد الرفع (أو فقط ملفاتهم عبر مسارهم)؛ المالك عبر service role server-side signed URL.
- `UPDATE/DELETE`: مرفوض للمستخدمين؛ إداري عبر service role عند الحاجة.

## مخاطر يجب معالجتها لاحقًا

- تخمين المسارات إن كانت قابلة للتنبؤ.
- تسريب روابط موقّعة طويلة العمر.
- رفع ملفات خبيثة (افحص النوع الحقيقي وليس الامتداد فقط).
