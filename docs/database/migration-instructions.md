# تعليمات تطبيق الهجرات يدويًا

> **لا تُطبَّق الهجرات تلقائيًا من هذا المستودع في هذه المرحلة.**

## المتطلبات

- مشروع Supabase جاهز.
- صلاحية مالك المشروع.
- نسخة احتياطية/بيئة staging مفضّلة قبل الإنتاج.

## الترتيب

طبّق ملفات `supabase/migrations/` تصاعديًا حسب اسم الملف الزمني من:

`20261101220001` → `20261101220012`

## خيار A — Supabase CLI (موصى به لاحقًا)

```bash
# من جذر المشروع بعد ربط المشروع يدويًا
npx supabase db push --dry-run
# بعد المراجعة الواعية فقط:
npx supabase db push
```

لا تنفّذ الأوامر أعلاه الآن إلا بموافقة صريحة لاحقة.

## خيار B — SQL Editor يدويًا

1. افتح SQL Editor في لوحة Supabase.
2. الصق محتوى كل ملف بالترتيب.
3. نفّذ ملفًا واحدًا في كل مرة وتحقق من النجاح قبل التالي.
4. عند أي فشل: أوقف التطبيق، لا تكمل عشوائيًا، راجع الخطأ.

## تحقق سريع بعد التطبيق (Staging)

```sql
-- يجب أن يعيد صفوف الجداول الجديدة
SELECT tablename
FROM pg_tables
WHERE schemaname = 'public'
ORDER BY tablename;

-- RLS مفعّل
SELECT relname, relrowsecurity, relforcerowsecurity
FROM pg_class
WHERE relnamespace = 'public'::regnamespace
  AND relkind = 'r'
ORDER BY relname;
```

## ما يجب عدم فعله

- عدم تشغيل الهجرات من جهاز يطبع أو يسجّل `service_role`.
- عدم تطبيق هجرة جزئية على الإنتاج ثم المتابعة بدون مراجعة.
- عدم إنشاء حسابات طلاب/مدرّسين تجريبية غير منضبطة في الإنتاج في هذه المرحلة.
